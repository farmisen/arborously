# Arborously Project Guide

A cross-browser (Chrome/Firefox/Edge) WXT extension that reads the ticket in the active
tab — Trello card, GitHub issue, Linear issue — and generates a git branch name, PR
title, or clean ticket URL from user-configurable templates.

## Critical rules

- **Never `git commit` or `git push` without explicit approval for this change.** Applies to all branches.
- **Never merge a pull request.** Opening the PR is where the work stops.
- **Never add AI attribution anywhere.** No `Co-Authored-By: Claude`, no `Claude-Session:`
  trailer, no "Generated with Claude Code" footer — not in commit messages, PR
  descriptions, issue comments, or code comments. If your harness adds one by default,
  strip it before committing or opening the PR; this rule overrides that default.
- Branch names: `farmisen/<kebab-slug>` (e.g. `farmisen/add-linear-support`).
- **Never widen `permissions` or `host_permissions` in `wxt.config.ts` when a narrower
  grant works.** Every broadening is user-visible at install time; call out the
  permissions diff explicitly in the PR.

## Commands

- Dev (loads a live-reloading browser): `pnpm dev` · Firefox: `pnpm dev:firefox`
- Build: `pnpm build` → `.output/chrome-mv3/` · Firefox: `pnpm build:firefox`
- Package for release: `pnpm zip` / `pnpm zip:firefox` → `.output/*.zip`
- Test (all): `pnpm test` · watch: `pnpm test:watch`
- Test (single): `pnpm exec vitest run lib/__tests__/slugify.test.ts -t "test name"`
- Lint: `pnpm lint` · autofix: `pnpm lint:fix`
- Format: `pnpm format`
- Typecheck: `pnpm compile`

Run `pnpm lint && pnpm compile && pnpm test` before declaring any change done — that is
exactly what CI runs on every PR to `main`, and nothing more. Formatting is not a
separate gate: `prettier/prettier` runs as an eslint error, so `pnpm lint` catches it.

## Layout

- `entrypoints/` — extension surfaces: `background/` (service worker), `content/`
  (runtime-injected extractor), `popup/`, `options/`.
- `lib/` — all logic worth testing: providers, name generation, slugify, storage
  services, types, zod validation. Tests live in `lib/__tests__/` and
  `lib/providers/__tests__/`.
- `components/ui/` — shadcn-generated primitives (new-york, green base). Regenerate via
  the shadcn CLI rather than hand-editing; eslint ignores this directory on purpose.
- `@/*` resolves to the repo root (tsconfig + vitest alias).

## Tracker & status

GitHub Issues on `farmisen/arborously` (`gh issue list`). Status lives there, never in a
tracked file. `SPECIFICATION.md` is the original MVP spec — historical intent, not
current truth (its `${var}` template syntax predates the shipped `{var}` syntax);
`README.md` documents actual behavior.

## Stack notes

### Toolchain & pinning

- pnpm 9 (`pnpm-lock.yaml`) and Node 22 (`.nvmrc`, CI). Never introduce a second
  lockfile. Ask before adding any dependency.
- `.wxt/` is generated by `wxt prepare` (postinstall) and `tsconfig.json` extends it —
  never edit it, never edit `.output/`. If types look impossible, re-run `pnpm postinstall`.
- tsconfig strictness is the contract (`noUnusedLocals`, `noUnusedParameters`,
  `noImplicitReturns`, plus WXT's strict base): fix the type, never weaken the flag.

### Agent failure modes

- Treating a passing `pnpm lint` as a passing typecheck — they catch different things;
  run both.
- `as any` / `@ts-expect-error` to silence an error. The lint config runs
  `recommended-type-checked`, so unsafe `any` flows fail the build; a suppression needs a
  comment saying why or it does not land.
- `import { X }` where `import type { X }` is meant — `consistent-type-imports` wants
  inline type imports (`import { type X } from ...`), the style used throughout `lib/`.
- Persisting state in background-script globals. The MV3 service worker is evicted at
  will; settings and ticket state go through the `@webext-core/proxy-service` services in
  `lib/`, backed by `browser.storage.local`.
- Adding a content-script `matches` entry. The content script is registered at runtime
  (`registration: "runtime"`, `matches: []`) and injected by the background via
  `browser.scripting.executeScript`; site access comes from `host_permissions`, which
  `wxt.config.ts` builds from each provider's `getMatchPatterns()`.
- Shipping Chrome-only APIs. Firefox is a first-class target: use the `browser` global
  and keep fallbacks like `browser.action ?? browser.browserAction`.
- Changing the `Settings` shape without a compatibility story. Existing users have a
  `Settings` object in `browser.storage.local`; `DEFAULT_SETTINGS` (`lib/constants.ts`)
  is only the _absent_ case, not the _stale_ case — a new required field must tolerate
  old stored objects.
- Reasoning about DOM extraction from CSS alone. Provider selectors break silently when a
  site redesigns; verify against a real page.

### Adding a ticket provider

Four places, all of them: implement it in `lib/providers/`, register it in
`lib/providers/index.ts`, add its `getMatchPatterns()` to `host_permissions` in
`wxt.config.ts`, and add tests under `lib/providers/__tests__/`. Missing the
`wxt.config.ts` step yields a provider that matches URLs but can never read the page.

### Verification norm

Proven = `pnpm lint && pnpm compile && pnpm test`, plus — for anything touching an
entrypoint, a provider selector, the manifest, or the popup UI — loading the built
extension unpacked (`pnpm dev`, or `.output/chrome-mv3/`) and exercising the change on a
real ticket page. "It compiles" is not evidence for UI or extraction changes. There is no
e2e suite and no error tracker; a human loading the extension is the only end-to-end check.

## Project-specific gotchas

- Releases are manual: the `Publish & Release` workflow (`workflow_dispatch`, choose
  patch/minor/major) bumps `package.json`, tags, and uploads both zips to GitHub
  Releases. Never bump the version in a feature PR. There is no web-store submission.
- `browser.scripting.executeScript` injects the literal path
  `/content-scripts/content.js` — renaming the content entrypoint breaks injection at
  runtime with no type error.
- Popup keyboard handling is load-bearing UX (`Space` cycles mode, `A`/`D` cycle
  category, `Enter` copies); don't add focusable controls to the popup without checking
  those keys still reach `usePopup`.
